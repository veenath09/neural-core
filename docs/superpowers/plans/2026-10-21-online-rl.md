# Monte Carlo RL, Part 2: Live Online RL — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The deployed controller keeps learning from the episodes it serves. Each finished episode is scored, stored, and turned into small policy-gradient updates, with rollback if quality drops. New models can join the pool while it runs, get explored, and get their cards updated from what they actually do. **This is the main deliverable of the RL work.** Part 1 (`2026-10-21-monte-carlo-rl.md`) is its warm start.

**Architecture:** The pieces are interface-agnostic, so the whole online loop runs and is tested against a **simulated stream** before any live call is paid for.

1. `ControllerSession` (C1) is a stateful per-episode wrapper: `reset` / `decide` / `after_round`. It turns live state into the same `View` the simulator uses, holds memory `W`, emits a `Strategy` and logs each decision with everything needed to replay it.
2. A `StepEnvironment` (C3) has two implementations: `SimStepEnv` (RouterBench simulator, reward quality from the noisy verifier, like live) and `LiveStepEnv` (`ExecutionEngine` and a live verifier).
3. `run_episode` (C2) drives a session through an environment and produces an `EpisodeLog` with per-decision rewards from `measurement.rl_reward.step_reward`.
4. `OnlineLearner` (C2) buffers logs. Every 16 new exploring episodes, it **replays** them through the current weights to get differentiable log-probs. It then applies an importance-weighted policy-gradient update (ratio clipped at 2.0) with the Part 1 bucketed baseline, plus a complexity distillation term toward a frozen teacher. Weights are published to the serving session **between** episodes. A simulator canary rolls back regressions.
5. `PoolState` (C2/C3) adds models at run time, one or a whole set: a probe card each, an exploration bonus that fades over 200 uses and is split across models arriving together, `ProfileUpdater` card updates from verifier outcomes, and retirement by masking (never deletion).

**Tech Stack:** Python 3.12, PyTorch, NumPy, pandas, matplotlib, pytest. The live step uses `execution/` adapters and an LLM provider, so it needs API keys.

## Global Constraints

- Everything in Part 1's Global Constraints still applies: reward, `LAMS`, `cost_ref`, policy outputs, baseline, no co-author trailer, and existing tests passing unedited.
- **Live reward quality** for a step is the verifier's `Score.quality` for that step's final round, in [0, 1]. Ground truth is never available live. `SimStepEnv` defaults to `quality_source="verifier"` (its `verifier_ok`, flip 0.15) so the simulated stream behaves like live; `"truth"` exists only for parity tests.
- **`n_steps`** for the reward is the number of steps the episode actually had, known when it ends. Rewards are assigned in `run_episode` after the episode finishes.
- **Explore vs serve:** each episode is run in `sample` mode with probability `explore_share`, otherwise in `serve` mode. Live `explore_share = 0.2`; simulated stream `1.0`. **Only `sample` episodes feed the policy-gradient loss.** All episodes feed card updates and monitoring.
- `OnlineConfig` defaults:
  - `update_every = 16` new sample-mode episodes per update
  - `replay_size = 48` extra episodes drawn uniformly from the buffer
  - `buffer_capacity = 2048` (FIFO)
  - `lr = 1e-5`, `beta = 0.001` (fixed), `clip_grad = 1.0`, `is_clip = 2.0`, `distill = 0.2`
  - `canary_every = 10` updates, `canary_episodes = 500` (fixed val skeletons, serve mode, every λ), `canary_tol = 0.05`
  - `monitor_window = 200`
- **Update loss** over the batch's choice slots:
  - `ρ = min(exp(logp_now.detach() − logp_behaviour), 2.0)`
  - `A = G − b[band, λ]`, normalised as in Part 1
  - `loss = −mean(ρ · A · logp_now) − β · mean(H) + 0.2 · mean_valid((σ(c_now) − c_teacher)²)`
- **Teacher:** a frozen copy of the starting checkpoint (Part 1's `rl/model.pt`) in eval mode. `c_teacher` is its complexity on the replayed views, because no exact band exists live.
- **Baseline:** load Part 1's `rl/baseline.pt` and keep updating it with `α = 0.05`.
- **Weights never change mid-episode.** The learner trains its own copy. `ControllerSession.reset` loads the latest published `state_dict`, and `policy_version` is stored in every `DecisionLog`.
- **Rollback:** a canary failure (quality at any λ below `reference − 0.05`, where `reference` is the starting checkpoint's canary quality) restores the last good weights and baseline, halves the lr, and publishes the restored weights. A drop of more than 0.05 in the rolling live reward over `monitor_window` episodes raises the alarm `"live_reward_drop"` but doesn't roll back, because the live signal is noisy.
- **Pool membership:** each card has a status: `warmup` (new, until 200 uses), `active`, or `retired`. **Indices never change.** Retiring a model masks it out of the CHOOSE and HALT masks; it's never deleted, so old logs still replay.
- **Exploration bonus,** split across everything warming up at the same time: `bonus_m = (1.0 / max(1, k_warmup)) · max(0, 1 − uses_m/200)` for `warmup` models, 0 otherwise. `k_warmup` is the number of models currently in `warmup`. The bonus is added to the model's policy logit in both modes, logged per decision, and reapplied during replay.
- **The baseline is pool-size independent:** `band = round(σ(c)·4)`, as in Part 1, so adding models never reshapes the baseline table.
- **Card updates:** after each episode, `ProfileUpdater(prior_weight=50).update_many(card, {step_type: (verifier_success_rate, n)})` for every model used. `mean_cost_usd` is the running mean of observed round costs. Updated cards are pushed with `Controller.set_cards`.
- Checkpoints: `<online_dir>/v{policy_version}.pt` for every published version, `<online_dir>/log.jsonl` with one row per episode and per update, `<online_dir>/pool.json` for the cards and their statuses.
- **Live spend is capped** with `RoutingSpendGuard`. Task 8 never runs without the user's explicit go-ahead and a stated dollar cap.

## Review Focus

1. **Replay must reproduce behaviour exactly.** With unchanged weights, replayed log-probs must equal the logged ones; otherwise the importance ratios are wrong. Test in Task 4.
2. **The session must match the simulator rollout.** A serve-mode session driven through `SimStepEnv` must take the same actions and get the same results as `rollout(policy="serve")`. Test in Task 2.
3. **Models added or retired mid-run,** possibly several at once: decisions logged before the pool changed must still replay, with the pool, mask and bonus they were made with. The baseline must keep its shape. Tests in Task 6.
4. **A publish during an episode** must not change that episode's weights. Test in Task 5.
5. **An unseen live prompt** must be embedded once and reused, not re-embedded on every pass. Test in Task 1.
