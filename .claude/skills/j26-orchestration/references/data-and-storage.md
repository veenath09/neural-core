**Current layout (October 2026).** The prototype writes:

- `data/raw/`: `routerbench_0shot.pkl`, `bge-small-en-v1.5/` (model weights)
- `data/processed/`: `prompts.parquet`, `pool.json`, `embeddings.npy`, `embedding_ids.json`, `episodes_{train,val,test}.parquet`
- `runs/<config>-s<seed>/`: `model.pt`, `metrics.json`, `residuals.png`, `residuals.json`, `memory_trace.csv`

These differ from the planned names above. Either set may be adopted by team agreement; until then, code reads the current layout.

## 2. Parquet schemas

### routerbench_binary.parquet

| Column | Type | Notes |
|---|---|---|
| `prompt_id` | string | stable id from RouterBench |
| `source` | string | benchmark name |
| `step_type` | string | equals `source` in v1 |
| `prompt_text` | string | |
| `{model}_correct` | int8 | 0/1, one column per pool model |
| `{model}_cost` | float64 | USD, one column per pool model |
| `difficulty` | int8 | pool models failing, 0..4 |

### skeletons_{split}.parquet

`episode_id, episode_type, prompt_ids (list<string>), budget_usd, split, seed, version`

### predictions.parquet (one row per round)

| Column | Notes |
|---|---|
| `eval_id, policy, config, seed, stage, operating_pt` | operating point is tau or lam |
| `episode_id, episode_type, step_id, step_index, round` | |
| `model_id, halt` | action |
| `oracle_model_id` | episode oracle's choice for this step (null for round 1) |
| `success_true, verifier_ok, cost_usd` | outcome |
| `confidence, complexity` | controller outputs |
| `surprise_norm, gate_rate` | diagnostics (null for baselines) |
| `budget_left_before` | |

### records/*.parquet

Columns mirror the dataclass fields; nested fields (`strategy`, `log_probs`, `entropy`, `diagnostics`, `components`) as JSON strings; `decision_state` as `list<float32>`.

## 4. Phase 3 database schema

`storage/migrations/001_init.sql`. Created in this order so foreign keys resolve.

```sql
CREATE TABLE model_cards (
    model_id TEXT PRIMARY KEY, provider TEXT NOT NULL, endpoint TEXT NOT NULL,
    price_in_per_m NUMERIC(12,6) NOT NULL, price_out_per_m NUMERIC(12,6) NOT NULL,
    price_date DATE NOT NULL, context_limit INT NOT NULL, max_output_tokens INT NOT NULL,
    supports_tools BOOLEAN NOT NULL, supports_reasoning BOOLEAN NOT NULL,
    capability JSONB NOT NULL, probe_version TEXT NOT NULL,
    avg_latency_ms REAL NOT NULL DEFAULT 0,
    status TEXT NOT NULL CHECK (status IN ('registered','warmup','active','retired')),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(), updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE model_profile_stats (
    model_id TEXT REFERENCES model_cards(model_id), step_type TEXT NOT NULL,
    n INT NOT NULL DEFAULT 0, mean_quality REAL NOT NULL DEFAULT 0,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(), PRIMARY KEY (model_id, step_type)
);

CREATE TABLE episodes (
    episode_id TEXT PRIMARY KEY, source TEXT NOT NULL CHECK (source IN ('live','sim')),
    episode_type TEXT, split TEXT, budget_total_usd NUMERIC(12,6),
    spent_usd NUMERIC(12,6) NOT NULL DEFAULT 0, status TEXT NOT NULL,
    final_quality REAL, started_at TIMESTAMPTZ NOT NULL DEFAULT now(), ended_at TIMESTAMPTZ
);

CREATE TABLE steps (
    step_id TEXT PRIMARY KEY, episode_id TEXT NOT NULL REFERENCES episodes(episode_id),
    step_index INT NOT NULL, step_type TEXT NOT NULL, prompt_ref TEXT NOT NULL
);
CREATE INDEX steps_episode_idx ON steps (episode_id, step_index);

CREATE TABLE training_runs (
    run_id TEXT PRIMARY KEY, config_name TEXT NOT NULL, stage TEXT NOT NULL,
    seed INT NOT NULL, config JSONB NOT NULL,
    started_at TIMESTAMPTZ NOT NULL DEFAULT now(), ended_at TIMESTAMPTZ
);

CREATE TABLE checkpoints (
    checkpoint_id TEXT PRIMARY KEY, run_id TEXT REFERENCES training_runs(run_id),
    parent_id TEXT REFERENCES checkpoints(checkpoint_id), path TEXT NOT NULL,
    temperature REAL NOT NULL, norm_stats_ref TEXT NOT NULL, contract_version TEXT NOT NULL,
    val_metrics JSONB NOT NULL, promoted BOOLEAN NOT NULL DEFAULT false,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE decisions (
    step_id TEXT REFERENCES steps(step_id), round INT NOT NULL,
    checkpoint_id TEXT REFERENCES checkpoints(checkpoint_id),
    strategy JSONB NOT NULL, log_probs JSONB NOT NULL, entropy JSONB NOT NULL,
    complexity_band SMALLINT NOT NULL, lam REAL, decision_state REAL[] NOT NULL,
    diagnostics JSONB NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (step_id, round)
);

CREATE TABLE executions (
    step_id TEXT, round INT, model_id TEXT REFERENCES model_cards(model_id),
    tools_called TEXT[] NOT NULL DEFAULT '{}', tokens_in INT NOT NULL, tokens_out INT NOT NULL,
    cost_usd NUMERIC(12,8) NOT NULL, latency_ms REAL NOT NULL, finish_reason TEXT,
    error TEXT, output_ref TEXT NOT NULL,
    PRIMARY KEY (step_id, round), FOREIGN KEY (step_id, round) REFERENCES decisions(step_id, round)
);

CREATE TABLE scores (
    step_id TEXT, round INT, quality REAL NOT NULL, verifier_ok BOOLEAN NOT NULL,
    lam REAL NOT NULL, reward REAL NOT NULL, components JSONB NOT NULL,
    scorer_version TEXT NOT NULL,
    PRIMARY KEY (step_id, round), FOREIGN KEY (step_id, round) REFERENCES executions(step_id, round)
);

CREATE TABLE eval_results (
    checkpoint_id TEXT REFERENCES checkpoints(checkpoint_id), eval_set TEXT NOT NULL,
    episode_type TEXT NOT NULL, operating_pt REAL NOT NULL, quality REAL NOT NULL,
    cost_usd REAL NOT NULL, ece REAL, n_episodes INT NOT NULL,
    PRIMARY KEY (checkpoint_id, eval_set, episode_type, operating_pt)
);
```

## 5. Experiment tracking files

Written by `common/tracking.py` `RunLogger`. Long format, so new metrics never change the schema.

`runs/{run_id}/run.json`

| Field | Notes |
|---|---|
| `run_id` | `{config}-{stage}-s{seed}-{yyyymmddHHMM}` |
| `component` | C1 to C4 |
| `config_name`, `stage`, `seed`, `config` | resolved config included |
| `status` | running, done, failed, stopped |
| `started_at`, `ended_at`, `contract_version` | |

`runs/{run_id}/metrics-*.parquet`: `run_id, step, split, metric, value, wall_s`

`runs/{run_id}/events-*.parquet`: `run_id, step, kind, detail, time` with kind in rollback, early_stop, checkpoint, alarm, note.

Phase 3 equivalents in PostgreSQL:

```sql
CREATE TABLE run_metrics (
    run_id TEXT REFERENCES training_runs(run_id), step INT NOT NULL, split TEXT NOT NULL,
    metric TEXT NOT NULL, value DOUBLE PRECISION NOT NULL, wall_s REAL NOT NULL
);
CREATE INDEX run_metrics_idx ON run_metrics (run_id, metric, step);

CREATE TABLE run_events (
    run_id TEXT REFERENCES training_runs(run_id), step INT NOT NULL, kind TEXT NOT NULL,
    detail TEXT, time TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## 6. Dashboard views (DuckDB)

Created by `ui/data.py` over the files above. The same names are recreated over PostgreSQL in Phase 3, so the dashboard does not change.

| View | Source | Grain |
|---|---|---|
| `runs` | `runs/*/run.json` | one row per run |
| `metrics` | `runs/*/metrics-*.parquet` | one row per metric value |
| `events` | `runs/*/events-*.parquet` | one row per event |
| `catalogue` | `data/clean/catalogue.json` | one row per ModelCard |
| `predictions` | `results/*/predictions.parquet` | one row per evaluated round |
| `step_final` | predictions | final round of each step |
| `episode_summary` | step_final + predictions | one row per policy, seed, operating point, episode: quality, cost, escalations |
| `frontier` | episode_summary | one row per policy, config, stage, seed, operating point |
| `by_type` | episode_summary | as frontier, split by episode type |
